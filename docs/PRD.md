## 1. 專案概述

### 1.1 背景與動機

隨著高齡化與少子化日趨嚴重，獨居老人的數量逐漸增加。這些長者常因無人照顧、慢性病纏身，加上不熟悉新興通訊設備，在發生特殊狀況時無法即時求助，可能過了數天甚至數月才被發現異狀。

為了能**每日確認獨居老人的生活情況**，我們開發一套專屬獨居老人使用的 Web 系統——「獨居老人生活管家」，透過簡單的介面設計讓長者能輕鬆操作，同時讓家屬與護工即時掌握老人的生活狀態。

### 1.2 目標用戶

| 角色 | 描述 |
| :--- | :--- |
| 獨居老人（長者） | 需要被照顧，但無法無時無刻受到照顧的族群。是系統的主要使用者，操作介面需極度簡化。 |
| 家屬 | 肩負照顧獨居老人的責任，但因工作或距離等原因無法時刻陪伴。需要遠端掌握長者狀況。 |
| 護工 | 提供老人生活護理的專業人員。需要瞭解長者的日常狀態以安排照護計畫。 |

### 1.3 核心價值主張

- **每日安全確認**：透過簡單的「每日回報」機制，讓家屬隨時知道長者是否安好。
- **用藥不遺忘**：系統化的事項提醒功能，確保長者按時服藥、完成日常事務。
- **緊急即時求助**：一鍵緊急按鈕，在意外發生時第一時間通知家屬。
- **操作極簡化**：介面針對長者設計，大按鈕、大字體、簡單流程。

## 3. 非功能需求（Non-functional Requirements）

| 類別 | 需求描述 | 具體標準 |
| :--- | :--- | :--- |
| 效能 | 系統要能穩定且長期運行 | 頁面載入時間不超過 3 秒 |
| 安全性 | 資料傳輸需加密，防止個資洩漏 | 密碼使用雜湊儲存（如 bcrypt），使用 Flask session 管理登入狀態 |
| 易用性 | 使用簡單幾個按鈕來操作 | 長者介面最多 3 個主要按鈕，字體不小於 24px |
| 可維護性 | 程式碼有清楚的結構與註解 | 使用 MVC 架構，函式需有 docstring |
| 相容性 | 支援主流瀏覽器 | 支援 Chrome、Edge、Safari 最新版本 |

### 技術限制

- **前端**：HTML / CSS / JavaScript（純前端，無框架）
- **後端**：Python + Flask
- **模板引擎**：Jinja2（由 Flask 渲染 HTML 頁面）
- **資料庫**：SQLite（使用 sqlite3 模組）
- **不採用前後端分離**：頁面由 Flask + Jinja2 一起渲染

# 產品需求文件 (PRD)：獨居老人生活管家系統

## 1. 專案概述
### 1.1 背景與動機
隨著高齡化與少子化日趨嚴重，獨居老人的數量逐漸增加。這些長者常因無人照顧、為慢性病所苦，同時不太會使用新興的通訊設備，在發生特殊狀況時無法即時求助，可能過了幾天或幾個月才被人發現陳屍於家中。為了解決此社會痛點，本專案旨在開發專屬獨居老人使用的軟體系統，每日確認長者的生活情況，並提供緊急求助與用藥提醒功能。

### 1.2 目標用戶
- **獨居老人**：需要被照顧，但沒辦法無時無刻都被照顧到的族群。
- **獨居老人的家人**：肩負照顧獨居老人的責任，但因工作或其他原因無法達成全天候照顧的族群。
- **護工**：提供老人生活護理專業服務的人員。

### 1.3 核心價值主張與目標
- **目標一**：解決難以取得獨居老人生活狀況的問題。
- **目標二**：解決獨居老人忘記吃藥的問題。
- **目標三**：解決無法在發生緊急狀況時即時採取行動的問題。
- **目標四**：解決無人陪伴獨居老人的問題。

## 2. 功能需求

### 2.1 事項提醒 (例如：用藥時間)
- **說明**：提醒長者記得完成日常事務。
- **使用者故事**：
  - 作為 **獨居老人家屬/護工**，我希望 **能設定用藥及日常事務的提醒時間**，以便 **確保長者能按時服藥及作息正常**。
  - 作為 **獨居老人**，我希望 **時間到時能收到簡單且大字體的提醒**，以便 **我不會忘記吃藥或完成重要事項**。

### 2.2 每日回報 (平安打卡)
- **說明**：確認長者是否安好。
- **使用者故事**：
  - 作為 **獨居老人**，我希望 **每天只需要按一個「我很好」的按鈕**，以便 **輕鬆地向家人報平安**。
  - 作為 **獨居老人家屬/護工**，我希望 **能查看長者的每日回報狀態**，以便 **在長者未回報時能及早發現異常並主動關心**。

### 2.3 緊急按鈕 (SOS)
- **說明**：遇到緊急事件時可以快速通報聯絡人。
- **使用者故事**：
  - 作為 **獨居老人**，我希望 **有一個明顯的緊急求助按鈕**，以便 **在發生意外時能一鍵通知家人或護工**。
  - 作為 **獨居老人家屬/護工**，我希望 **在長者按下緊急按鈕時收到即時通知**，以便 **能在第一時間採取救援行動**。

### 2.4 關懷陪伴與簡單問候
- **說明**：系統定時發送簡單問候語，解決無人陪伴問題。
- **使用者故事**：
  - 作為 **獨居老人**，我希望 **系統能偶爾推播溫馨問候或生活小貼士**，以便 **讓我感覺有人關心、減少孤獨感**。

### 2.5 聯絡人與帳號綁定管理
- **說明**：設定緊急聯絡人與照護關係。
- **使用者故事**：
  - 作為 **獨居老人家屬**，我希望 **能將我的帳號與長者的帳號綁定，並設定緊急聯絡電話**，以便 **接收通知與進行管理**。

## 3. 非功能需求

### 3.1 易用性
- **極簡介面**：使用簡單幾個按鈕來操作，按鈕需夠大、對比度高，文字需清晰易讀，符合長者視覺與操作習慣。

### 3.2 效能與穩定性
- **穩定長期運行**：系統要能穩定且長期運行，確保緊急求助與每日回報功能隨時可用，不會因當機而延誤救援。

### 3.3 安全性
- **資料加密**：資料傳輸需加密，防止個資洩漏，確保長者健康資料與聯絡人資訊安全。

### 3.4 技術限制
- **技術棧**：使用 Flask 作為後端框架，Jinja2 進行前端模板渲染，SQLite 作為資料庫管理。

### 3.5 範圍外限制 (Out of Scope)
- 本次開發 **不包含**：通話功能。
- 本次開發 **不包含**：跌倒偵測功能。

## 4. MVP 範圍 (Minimum Viable Product)

### 🔴 Must Have (必須具備)

### 🟢 Nice to Have (有了更好)
- 系統自動推播每日關懷問候語。
- 回報紀錄的歷史數據圖表（供護工參考）。
